# 交易所前端统一验收评分表 v1.0

项目：BTCBOX  
对标目标：Binance / OKX / Bybit / Coinbase 的成熟交易所体验  
适用范围：全站产品验收、阶段验收和上线前验收

## 1. 上线标准

- 总分必须 ≥ 85 / 100。
- 必须没有任何一票否决项。
- 评分必须有证据，不允许仅凭主观印象打分。
- 任意一票否决项触发：禁止上线，即使总分达到95分也不例外。

| 评级 | 分数 | 结论 |
|---|---:|---|
| S级 | 95–100 | 卓越 |
| A级 | 90–94 | 优秀 |
| B级 | 85–89 | 达到上线评分门槛 |
| C级 | 80–84 | 未达上线门槛 |
| D级 | 80以下 | 禁止上线 |

## 2. 功能组（50分）— 3号 Business Team

目标：功能完整、数据准确、系统稳定。

### F1 功能完整度（20分）

| 项目 | 分值 |
|---|---:|
| 登录注册 | 2 |
| 安全中心 | 2 |
| KYC认证 | 2 |
| 资产中心 | 3 |
| 充值提现 | 3 |
| 行情系统 | 2 |
| 现货交易 | 3 |
| 合约交易 | 3 |
| **小计** | **20** |

评分必须检查实际可用能力、真实数据、权限与错误状态。仅有页面或按钮不能得满分；后端未接通或功能明确不可用时，必须按实际状态评分，不得假定完成。

### F2 数据正确性（15分）

检查：
- 资产余额正确。
- 持仓数据正确。
- 订单状态正确。
- 成交记录正确。
- 盈亏计算正确。

评分：
- 无错误：15分。
- 轻微错误：10分。
- 中等错误：5分。
- 严重错误或关键数据不可信：0分。

### F3 异常处理（10分）

检查：
- 网络断开。
- API异常。
- WebSocket重连。
- 权限异常。
- 余额不足。
- 重复提交。

按覆盖完整度、错误可恢复性、是否防止错误资金/订单状态评分。

### F4 系统稳定性（5分）

检查：
- 无崩溃。
- 无白屏。
- 无死循环。
- 无重大内存泄漏。

## 3. 交互组（30分）— 2号 Interaction Team

目标：用户操作流畅、高效、专业。

### U1 用户流程（10分）

关键流程：
- 注册。
- 登录。
- KYC。
- 充值。
- 下单。
- 平仓。
- 提现。

评分：
- 完全顺畅：10分。
- 少量阻塞：7分。
- 多处阻塞：3分。
- 严重问题：0分。

### U2 操作反馈（8分）

检查：
- Loading。
- Success。
- Error。
- Warning。
- Confirm。
- Toast。

检查反馈时机、文案准确性、状态持续时间、可关闭性、重复触发和无障碍交互。成功反馈必须由真实业务结果触发。

### U3 实时体验（6分）

检查：
- K线刷新。
- 深度刷新。
- 订单刷新。
- 持仓刷新。
- 资产刷新。

检查更新及时性、断线提示、重连、数据过期状态和 UI 同步，不以静态假数据替代实时验证。

### U4 一致性（6分）

检查：
- 按钮行为一致。
- 表单行为一致。
- 弹窗行为一致。
- 表格行为一致。

## 7. 一票否决项

出现任意一项，直接禁止上线：

- [ ] 无法登录。
- [ ] 无法下单。
- [ ] 无法充值。
- [ ] 无法提现。
- [ ] 资产计算错误。
- [ ] 持仓计算错误。
- [ ] WebSocket频繁断线，导致关键状态不可靠。
- [ ] 页面崩溃。
- [ ] 白屏。
- [ ] 数据错乱。

任何一项未测试不能默认通过，必须标记 NOT TESTED；如果上线验收时关键路径无法验证，则不能签署上线通过。

注意：不得为了通过验收在生产环境执行真实充值、提现或交易。应使用获批的隔离测试环境和测试账户；没有安全测试条件时标记 NOT TESTED，并保持上线门禁未通过。
